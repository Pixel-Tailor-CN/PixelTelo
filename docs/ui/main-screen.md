# 主页面 UI 规范

## 概览

主页面是 Pixel Telo 的入口点。必须严格遵守 **Material3** 设计规范，并支持 **Monet (动态取色)**。

## 状态

### 1. 数据完整性检查 (初始/空状态)

* **触发条件**: 当 `Repository.recordCount == 0` 时。
* **UI 元素**:
    * **状态指示**: 醒目警告卡片，标题“离线号码库未下载”，说明“下载后可使用离线识别”。
    * **操作**: “下载”按钮进入现有设置下载入口，不自动执行下载。
    * **反馈**: 用户在设置中明确启动下载后，沿用原下载进度显示。

### 2. 已填充状态 (正常运行)

* **触发条件**: 当 `Repository.recordCount > 0` 时。
* **UI 元素**:
    * **状态卡片**: 显示“受保护”或“运行中”。
    * **统计**: 显示已拦截通话数量、上次更新时间。
    * **操作**: 设置入口、手动检查更新。

### 3. 历史记录名单状态

* 历史记录中的 `CurrentListState` 由 `HomeViewModel` 使用 `PhoneNumberRuleMatcher` 计算，
  与 `UserListRepository` 的实际来电匹配共享同一套精确/前缀规则。
* 对明确国际号码，`+国家代码` 与 `00国家代码` 视为等价；没有 `+`/`00` 标记的纯数字号码保持
  独立格式域，不会在历史名单状态中跨格式显示为命中。

### 4. 数据源下线提示 (WarningCard)

* **触发条件**: `HomeViewModel.unavailableSourceWarning` 非空，即 source 状态的 `backendId` 与当前
  `QueryBackendState.Ready.backendId` 匹配，且用户已启用的联网查询 source 被该 Backend 下线。source
  清单在应用启动时后台刷新一次，不阻塞首页首帧；切换窗口先隐藏旧 Backend 告警，刷新失败沿用当前
  Backend 缓存，不误报其他 Backend 的 source。
* **UI 元素**: 不可忽略的 WarningCard，列出下线的 source ID，提供“调整数据源”按钮。
* **导航**: 按钮经 `MainActivity` 协调，先打开 `SettingViewModel` 的 source 设置 BottomSheet，
  再切换到设置页。用户修正配置后卡片自动消失。

### 5. 自建服务安全提示 (WarningCard)

* **触发条件**: 用户选择了自建 Backend，但 `QueryBackendProvider` 因配置/凭据不可用、TLS/Pin、
  服务版本、API Version、Instance ID 或身份 Header 问题发布 `Blocked` 状态。
* **非触发条件**: 偶发网络超时、429 和普通 5xx 不形成持续卡片；首页不主动执行健康轮询。
* **UI 元素**: 不可忽略的 WarningCard，只展示本地化安全分类和“调整查询服务”操作，不展示 Token、
  完整 URL、Pin、Instance ID、服务端响应正文或异常堆栈。
* **导航**: 操作跳转到设置页的在线查询区域。用户可重新测试、修改配置或显式切回官方；只有完整重验证
  成功才解除阻止状态。
* **恢复边界**: 运行期安全阻止在发布卡片前写入独立持久哨兵；进程被终止后仍保持 Blocked。普通
  Backend 存储命令失败只展示本次操作错误，不撤销仍可用的旧 Backend，也不触发安全卡片。
* **来电行为**: 卡片只反映 Provider 状态；实际来电查询在 Snapshot 不可用时直接 Fail Open，不回退
  官方实时查询。

## 记录详情反馈入口

* 点击拦截记录卡片弹出的详情 BottomSheet 中，若记录带有 `querySource` 则展示命中来源。
* 只有 `queryBackendId == "official"`、存在有效 Token 且 `feedbackStatus == PENDING` 时，才展示
  “结果准确 / 结果不准确”两个操作；提交期间按钮禁用；
  可重试失败展示错误并允许重试（状态保持 `PENDING`）。
* 终态（`POSITIVE`/`NEGATIVE`/`ALREADY_SUBMITTED`/`EXPIRED`/`INVALID`）只展示状态文字，
  不再提供提交按钮；自建记录固定为 `UNAVAILABLE`，不展示反馈区域。

## 社区上报与我的上报

* 详情的“上报骚扰”与质量反馈区域独立；所有记录提供资格说明，有有效官方 Token 才能提交，不补查、不自动加黑名单。
  每次提交先确认向官方发送号码及安装标识；不上传通讯录或录音。关闭详情或换目标不会把迟到结果显示到另一记录。
* 首页顶部“我的上报”图标与设置中的入口共用同一二级页，不增加底部导航；无本地记录、自建或离线模式下仍可进入官方历史。
  进入时关闭详情，页面隐藏主导航，返回原 Tab；只有进入页面才加载列表。页面不保留常驻说明区，
  旧身份不可恢复的说明只出现在“建立新上报身份”的二次确认和设置页备份说明中。
* 云端列表按 report_id 去重，每页 20、内存最多 100 行，支持加载更多；刷新使用下拉手势回到最新一页（丢弃已加载分页）。
  刷新失败时保留已显示内容，在列表顶部提示可能过时、可下拉重试；列表为空时失败改用居中空状态，按失败类型给“重试”或“建立新上报身份”。
* 列表沿用「来电记录」页的设计语言：surfaceContainerLow 扁平卡片 + 身份行（号码 + 右上时间）+ 无底色次要信息行 + 唯一状态徽章。
  身份行右上为该上报最近一次状态变化时间，更早的上报时间在次要行标为“上报于 …”；
  徽章显示“有效／已撤回／已被管理员作废／状态未知”，作废沿用 error 红；读取时的社区状态与作废说明退成无底色次要行，
  未知记录状态禁止写操作。撤回与删除历史使用描边 chip，删除沿用低强调红。
* 作废记录说明当前设备不能再上报此号码，其他号码不受影响，删除不解除限制；只有此前已撤回的历史才能删除。
* 有效记录先二次确认撤回，再可确认删除历史；作废记录无撤回动作，仅此前已撤回的作废历史保留删除动作。
  失败不提前移除。响应丢失提示结果待核实，不把重试显示成新增一票。
* 身份损坏显示新身份确认及旧管理权不可恢复警告；卸载、清数据和手动恢复不能恢复旧身份。
* 历史社区状态与真实社区拒接原因在记录详情中明确标为“历史快照”，首页列表不再重复展示；重查展示本次查询快照，不覆盖历史事实。
  设置中的社区拦截默认关闭，仅官方在线查询有效；备份说明引导使用手动备份迁移运行时数据。

## 拦截记录展示

* 使用 Paging 3 分页加载：每页 30 条，预取 10 条，最多在内存保留约 90 条记录。
* 匹配到联系人时，卡片展示姓名、完整号码和时间，允许按宽度和字号自适应换行；未命中、权限缺失或联系人查询失败时只显示号码身份。
* 归属地在号码下方的次要行展示，省市相同只显示一次，空值不显示占位，不显示运营商。
* 联系人查询范围限定为当前 Paging 已加载窗口，联系人变化后只刷新当前窗口。
* 详情 BottomSheet 同步展示联系人姓名、完整号码和归属地，所有号码操作仍使用原始号码。
* Paging refresh 失败时保留已经显示的记录，并在列表内提供轻量重试入口。
* 底部导航使用“来电记录”。首页顶部保留“我的上报”，存在记录时在更多菜单中提供“全部清空”；执行前必须通过确认对话框说明该操作不可撤销，
  且只删除拦截记录，不影响黑名单、白名单、骚扰号码库和本地号码标签。清空完成后刷新 Paging 与 Smartspacer 计数。

## 黑白名单展示与搜索

* 名单页沿用「来电记录」页的设计语言：`surfaceContainerLow` 扁平卡片、身份行（号码或关键词 + 右上时间）、
  无底色的次要信息行与单一状态徽章。前缀、标签、归属地规则分别用图标加短文案标明匹配方式，
  前缀规则同时保留目标 `400*` 与「前缀匹配」说明；普通号码不创建多余次要行。
* 「强制拦截」使用 error 色，与「暂不生效」的中性灰徽章互不混淆。归属地规则在开启「不联网查询」后不生效，
  卡片在徽章之外给出原因说明，不占用错误色。前缀规则的前导值注入读屏语义，避免只读出 `400*` 字面量。
* 顶部搜索框仅在黑白名单条目总数为 0 时隐藏，避免切换 Tab 造成 TabRow 抖动；存在查询词时始终保留并提供清除动作。
  搜索只匹配已加载的本地名单（号码、备注与纯数字包含），不因搜索触发联网查询，无结果使用独立空状态并可直接清除搜索。
* 查询词跨黑名单与白名单共享；新增或编辑保存后不清空也不按查询词自动过滤，保留用户输入并以提示确认保存结果。
* 键盘弹出时「添加条目」悬浮按钮抬升到键盘上方；列表底部预留悬浮按钮高度，滚动到末尾时最后一条不被遮挡。

## 查询失败提示与标签规则

* 联网失败仍放行并允许手动重试。历史记录和 Overlay 显示具体分类；重试弹窗与设置中的拦截测试
  提供号码检查、服务配置检查、稍后重试或切换可用数据源等对应建议，不展示原始服务端错误。
* 区分参数无效、认证/授权失败、响应格式不兼容、上游超时、服务/上游不可用、反馈凭据签发失败，
  保留原有连接失败、客户端超时、限流、服务异常和 Backend 未就绪提示。旧历史记录不追溯推断具体原因。
* 标签规则的新增和编辑表单提供“精确匹配 / 包含匹配”单选项，名单卡片同步标明匹配方式。
  新规则默认精确，既有规则升级后保持精确；包含匹配说明明确不作用于用户手写本地标签。

## 本地号码标签展示与管理

* 列表卡片以独立徽章展示本地标签和数据源标签，去掉重复的字段前缀；本地标签使用编辑图标与主强调色，来源标签使用云图标，并提供各自的无障碍描述。两者不拼接或互相冒充，空白则隐藏。
* 本地标签按当前 Paging 已加载窗口动态关联：同一归一化号码的多条历史记录共享当前标签，
  修改或删除后窗口内立即刷新，不把标签复制进 `BlockedCall`。
* “显示本地号码标签”默认关闭。关闭时首页不建立窗口标签订阅，列表普通身份区域和详情身份区
  不显示本地标签；编辑、删除、统一管理和备份恢复不受影响。
* 详情 BottomSheet 始终提供本地标签管理入口：尚未设置/当前标签，以及设置、修改、删除。
  管理区不读取显示开关。首次创建只能从已有来电记录进入，不支持任意输入号码新建。
* 统一管理页从设置“数据与上报”分组进入，是现有 HorizontalPager 之上的非底部二级页面，返回后仍停留
  在设置 Tab。页面只支持搜索、编辑和删除已有标签。
* 来电详情采用扁平布局：身份摘要直接展示联系人、完整号码、归属地、时间及历史处理结果，随后提供独立快捷命令。来源、本地标签、完整备注、耗时和社区历史快照直接可读，不再提供“记录信息”或“更多操作”折叠开关。标签快捷动作打开编辑弹窗，已有标签的删除入口位于弹窗内并保留二次确认。

## 设计组件

* **TopAppBar**: 简单的 Material3 TopAppBar。
* **Scaffold**: 标准 Scaffold。
* **Cards**: 使用 `OutlinedCard` 或 `ElevatedCard` 进行状态显示。
* **Theme**: 在支持的设备 (Android 12+) 上必须使用 `dynamicLightColorScheme` 和
  `dynamicDarkColorScheme`。

## 分区详情与来电记录卡

> 本节补充当前组件布局和自适应规则；业务状态与数据规则保持原定义。

- 首页按设备本地日期显示“今天 / 昨天 / 具体日期”分组，跨 Paging 页连续同日记录不重复分组。分组内时间仅显示时分，详情和其他入口继续使用完整日期时间。
- 首页记录卡使用 Monet 的 `surfaceContainerLow` 浅色圆角表面，号码或联系人作为主强调，时间位于右上。归属地、来源标签和可选本地标签在次要行展示；历史处理结果独立成行，仅保留一个结果图标。成功记录提供尾部箭头，查询失败保留具体分类摘要和带文字的重试入口，当前名单状态继续独立显示。
- 来源及本地标签使用无底色的图标与文字，保留 Cloud/Edit 图标、独立语义描述及本地强调色；三项次要信息均不可见时不创建空行。字体缩放超过 1.3 时，结果与具体原因占满宽度，重试按钮置于下方独立行；普通字号保留尾部重试布局。
- 点击记录卡打开单一详情 BottomSheet。首先展示号码、联系人、归属地与完整时间，随后将云端骚扰标签和识别来源放入同一自适应行；窄屏或长内容自然换行。来源使用非交互小标记，只显示真实来源名，空白隐藏，长内容不截断。标记使用低强调 Monet 表面、细边框、约 8dp 圆角与小号文字，可见高度约 24dp 并随字体自然增长；无障碍仍说明识别来源。来源标签、本地标签和实际历史处理结果保持独立语义。
- 来电详情首次打开直接展开，跳过半展开状态，内部保持纵向滚动，返回和外部点击仍可关闭；重查及其他 BottomSheet 保持原状态行为。详情位置与时间之间使用带空格的“ · ”分隔，位置为空时只显示时间。
- 详情云端标签、来源小标记和实际历史处理结果共用一个 FlowRow，横向间距 8dp、换行间距 4dp；常见普通字号内容可同行，窄屏、大字体或失败原因较长时自然换行，不截断或缩小文字。本地标签继续独立显示。身份命令区外层间距为 6dp，上方留白 16dp、下方 8dp，横向仍为 20dp；不压缩操作芯片的 48dp 触摸区域。
- 号码操作使用三个独立描边 AssistChip：加黑名单、加白名单、本地标签，可见高度约 32dp，Material3 触摸区域至少 48dp，FlowRow 随宽度和字号换行。各命令允许规则并存，不再显示下方作用范围说明及其留白。
- 加黑和加白点击后先打开确认对话框，显示完整号码、对应规则影响与明确的加入动作。取消、Back 或外部关闭只退出确认，详情保持且不写规则。标签白名单同样先确认具体标签及影响其他同标签号码，再调用原动作；本地标签仍使用独立编辑保存。
- 名单确认状态和提交协程绑定当前记录、号码及标签，详情关闭或切换目标即丢弃；写入前复核目标，提交期间防重复。成功或已存在沿用原提示；异常在确认框显示失败并允许重试，取消异常继续抛出，不当作成功或重复。
- 标签白名单使用独立操作行，标题“将「标签」加入标签白名单”，副标题说明匹配其他同标签号码；只在存在识别来源标签时显示，本地手写标签不充当识别来源规则。
- 备注、识别来源、处理耗时与社区历史快照均在详情直接展开显示。社区历史快照只在详情展示，明确区分历史社区判断和当前名单事实。质量反馈与社区上报保留独立状态；详情已提交上报状态提供“查看上报”导航，首页和设置的全局入口保留。
- “历史记录”小节使用紧凑键值布局，直接展示社区标记的当时状态、完整原始备注和本地/网络处理耗时，不提供折叠入口。`UNKNOWN` 保留原条件隐藏规则，真实 `communityBlockApplied` 继续单独说明当时社区拦截原因。窄屏及字体缩放超过 1.3 时，字段名和值上下排列，完整内容自然增长。
- 详情根滚动容器不设统一横向留白，各正文分区使用单层 20dp 横向边距，主要分隔线贯穿 Sheet 宽度。按身份与命令、条件标签白名单、历史、反馈与上报、底部管理操作排列；标签白名单不存在时不创建空分区，主要细分隔线共 3–4 条。历史和反馈分区纵向边距为 12dp，历史字段间距 4dp，大字体仍允许自然堆叠。
- 详情移除根容器额外的 32dp 底部留白，保留底部操作分区 12dp 纵向边距及 ModalBottomSheet 默认管理的一份系统安全区，不硬编码导航栏高度，也不修改重查 Sheet。
- 准确性反馈和独立社区上报区域合入整宽 Monet 分区，使用 `surfaceContainerHigh` 与 Sheet 背景形成可辨识层级，正文仅一层 20dp 横向留白，无边框和阴影，标题“这次识别准确吗？”。准确/不准确为独立等宽描边按钮，约 18dp 图标、约 40dp 可见高度，沿用 Material3 至少 48dp 触摸区域，保留自然换行及原有反馈资格、提交禁用、失败和终态逻辑。
