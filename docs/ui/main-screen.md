# 主页面 UI 规范

## 概览

主页面是 Pixel Telo 的入口点。必须严格遵守 **Material3** 设计规范，并支持 **Monet (动态取色)**。

## 状态

### 1. 数据完整性检查 (初始/空状态)

* **触发条件**: 当 `Repository.recordCount == 0` 时。
* **UI 元素**:
    * **状态指示**: 醒目的警告卡片或插图，指示“无数据/数据库为空”。
    * **操作**: 主按钮“下载数据”（或“初始化”）。
    * **反馈**: 点击操作后显示下载进度指示器 (LinearProgressIndicator)。

### 2. 已填充状态 (正常运行)

* **触发条件**: 当 `Repository.recordCount > 0` 时。
* **UI 元素**:
    * **状态卡片**: 显示“受保护”或“运行中”。
    * **统计**: 显示已拦截通话数量、上次更新时间。
    * **操作**: 设置入口、手动检查更新。

### 3. 历史记录名单状态

* 历史记录中的 `CurrentListState` 由 `HomeViewModel` 使用 `PhoneNumberRuleMatcher` 计算，
  与 `UserListRepository` 的实际来电匹配共享同一套精确/前缀规则。
* 对明确国际号码，`+国家代码` 与 `00国家代码` 视为等价；没有 `+`/`00` 标记的纯数字号码保持
  独立格式域，不会在历史名单状态中跨格式显示为命中。

### 4. 数据源下线提示 (WarningCard)

* **触发条件**: `HomeViewModel.unavailableSourceWarning` 非空，即 source 状态的 `backendId` 与当前
  `QueryBackendState.Ready.backendId` 匹配，且用户已启用的联网查询 source 被该 Backend 下线。source
  清单在应用启动时后台刷新一次，不阻塞首页首帧；切换窗口先隐藏旧 Backend 告警，刷新失败沿用当前
  Backend 缓存，不误报其他 Backend 的 source。
* **UI 元素**: 不可忽略的 WarningCard，列出下线的 source ID，提供“调整数据源”按钮。
* **导航**: 按钮经 `MainActivity` 协调，先打开 `SettingViewModel` 的 source 设置 BottomSheet，
  再切换到设置页。用户修正配置后卡片自动消失。

### 5. 自建服务安全提示 (WarningCard)

* **触发条件**: 用户选择了自建 Backend，但 `QueryBackendProvider` 因配置/凭据不可用、TLS/Pin、
  服务版本、API Version、Instance ID 或身份 Header 问题发布 `Blocked` 状态。
* **非触发条件**: 偶发网络超时、429 和普通 5xx 不形成持续卡片；首页不主动执行健康轮询。
* **UI 元素**: 不可忽略的 WarningCard，只展示本地化安全分类和“调整查询服务”操作，不展示 Token、
  完整 URL、Pin、Instance ID、服务端响应正文或异常堆栈。
* **导航**: 操作跳转到设置页的在线查询区域。用户可重新测试、修改配置或显式切回官方；只有完整重验证
  成功才解除阻止状态。
* **恢复边界**: 运行期安全阻止在发布卡片前写入独立持久哨兵；进程被终止后仍保持 Blocked。普通
  Backend 存储命令失败只展示本次操作错误，不撤销仍可用的旧 Backend，也不触发安全卡片。
* **来电行为**: 卡片只反映 Provider 状态；实际来电查询在 Snapshot 不可用时直接 Fail Open，不回退
  官方实时查询。

## 记录详情反馈入口

* 点击拦截记录卡片弹出的详情 BottomSheet 中，若记录带有 `querySource` 则展示命中来源。
* 只有 `queryBackendId == "official"`、存在有效 Token 且 `feedbackStatus == PENDING` 时，才展示
  “结果准确 / 结果不准确”两个操作；提交期间按钮禁用；
  可重试失败展示错误并允许重试（状态保持 `PENDING`）。
* 终态（`POSITIVE`/`NEGATIVE`/`ALREADY_SUBMITTED`/`EXPIRED`/`INVALID`）只展示状态文字，
  不再提供提交按钮；自建记录固定为 `UNAVAILABLE`，不展示反馈区域。

## 社区上报与我的上报

* 详情的“上报骚扰”与质量反馈区域独立；所有记录提供资格说明，有有效官方 Token 才能提交，不补查、不自动加黑名单。
  每次提交先确认向官方发送号码及安装标识；不上传通讯录或录音。关闭详情或换目标不会把迟到结果显示到另一记录。
* 首页顶部“我的上报”图标与设置中的入口共用同一二级页，不增加底部导航；无本地记录、自建或离线模式下仍可进入官方历史。
  进入时关闭详情，页面隐藏主导航，返回原 Tab；只有进入页面才加载列表。
* 云端列表按 report_id 去重，每页 20、内存最多 100 行，支持加载更多及“刷新并回到最新”；失败保留内容并标明可能过时。
  行分别显示“我的上报有效／已撤回／已被管理员作废”和读取时的社区状态，未知记录状态禁止写操作。
  作废记录展示作废时间、此前撤回时间（若有），说明当前设备不能再上报此号码，其他号码不受影响，删除不解除限制。
* 有效记录先二次确认撤回，再可确认删除历史；作废记录无撤回动作，仅此前已撤回的作废历史保留删除动作。
  失败不提前移除。响应丢失提示结果待核实，不把重试显示成新增一票。
* 身份损坏显示新身份确认及旧管理权不可恢复警告；卸载、清数据和手动恢复不能恢复旧身份。
* 历史社区状态与真实社区拒接原因在记录详情中明确标为“历史快照”，首页列表不再重复展示；重查展示本次查询快照，不覆盖历史事实。
  设置中的社区拦截默认关闭，仅官方在线查询有效；备份说明引导使用手动备份迁移运行时数据。

## 拦截记录展示

* 使用 Paging 3 分页加载：每页 30 条，预取 10 条，最多在内存保留约 90 条记录。
* 匹配到联系人时，卡片展示姓名、完整号码和时间，允许按宽度和字号自适应换行；未命中、权限缺失或联系人查询失败时只显示号码身份。
* 归属地与号码紧凑组合，省市相同只显示一次，空值不显示占位，不显示运营商。
* 联系人查询范围限定为当前 Paging 已加载窗口，联系人变化后只刷新当前窗口。
* 详情 BottomSheet 同步展示联系人姓名、完整号码和归属地，所有号码操作仍使用原始号码。
* Paging refresh 失败时保留已经显示的记录，并在列表内提供轻量重试入口。
* 首页存在记录时，TopAppBar 展示“全部清空”操作；执行前必须通过确认对话框说明该操作不可撤销，
  且只删除拦截记录，不影响黑名单、白名单、骚扰号码库和本地号码标签。清空完成后刷新 Paging 与 Smartspacer 计数。

## 查询失败提示与标签规则

* 联网失败仍放行并允许手动重试。历史记录和 Overlay 显示具体分类；重试弹窗与设置中的拦截测试
  提供号码检查、服务配置检查、稍后重试或切换可用数据源等对应建议，不展示原始服务端错误。
* 区分参数无效、认证/授权失败、响应格式不兼容、上游超时、服务/上游不可用、反馈凭据签发失败，
  保留原有连接失败、客户端超时、限流、服务异常和 Backend 未就绪提示。旧历史记录不追溯推断具体原因。
* 标签规则的新增和编辑表单提供“精确匹配 / 包含匹配”单选项，名单卡片同步标明匹配方式。
  新规则默认精确，既有规则升级后保持精确；包含匹配说明明确不作用于用户手写本地标签。

## 本地号码标签展示与管理

* 列表卡片以独立徽章展示本地标签和数据源标签，去掉重复的字段前缀；本地标签使用编辑图标与主强调色，来源标签使用云图标，并提供各自的无障碍描述。两者不拼接或互相冒充，空白则隐藏。
* 本地标签按当前 Paging 已加载窗口动态关联：同一归一化号码的多条历史记录共享当前标签，
  修改或删除后窗口内立即刷新，不把标签复制进 `BlockedCall`。
* “显示本地号码标签”默认关闭。关闭时首页不建立窗口标签订阅，列表普通身份区域和详情身份区
  不显示本地标签；编辑、删除、统一管理和备份恢复不受影响。
* 详情 BottomSheet 始终提供本地标签管理入口：尚未设置/当前标签，以及设置、修改、删除。
  管理区不读取显示开关。首次创建只能从已有来电记录进入，不支持任意输入号码新建。
* 统一管理页从设置“数据与上报”分组进入，是现有 HorizontalPager 之上的非底部二级页面，返回后仍停留
  在设置 Tab。页面只支持搜索、编辑和删除已有标签。
* 来电详情采用扁平布局：身份摘要直接展示联系人、完整号码、归属地、时间及历史处理结果，随后提供独立快捷命令。来源、本地标签、完整备注、耗时和社区历史快照直接可读，不再提供“记录信息”或“更多操作”折叠开关。标签快捷动作打开编辑弹窗，已有标签的删除入口位于弹窗内并保留二次确认。

## 设计组件

* **TopAppBar**: 简单的 Material3 TopAppBar。
* **Scaffold**: 标准 Scaffold。
* **Cards**: 使用 `OutlinedCard` 或 `ElevatedCard` 进行状态显示。
* **Theme**: 在支持的设备 (Android 12+) 上必须使用 `dynamicLightColorScheme` 和
  `dynamicDarkColorScheme`。

## Argon 扁平详情与紧凑记录卡

> 本节补充当前组件布局和自适应规则；业务状态与数据规则保持原定义。

- 首页记录卡直接展示联系人（若有）、号码、归属地、时间、结果、来源标签和可选本地标签。结果、来源、本地标签使用不同图标与语义描述；查询失败保留分类摘要与原重试入口，当前名单状态继续独立显示。
- 点击记录卡打开单一详情 BottomSheet。号码下直接显示来电时间与 FlowRow 快捷命令：加入黑名单、加入白名单、本地标签；它们是独立命令，允许规则并存。识别来源标签仍使用单独的“加入标签白名单”条件操作，本地手写标签不充当识别来源规则。
- 备注、查询来源、处理耗时与社区历史快照均在详情直接展开显示。社区历史快照只在详情展示，明确区分历史社区判断和当前名单事实。质量反馈与社区上报分区显示；详情不再提供“我的上报”导航，首页和设置的全局入口保留。
- 社区区域优先显示资格检查、提交中、已接受、资格说明、可提交/失败重试状态。提交前仍需确认向官方发送号码和安装标识；失败提示保留结果不确定含义，不自动重试。
- 详情底部直接提供“保存到通讯录”和删除记录。保存继续使用系统 Intent；删除继续沿用原确认对话框。标签编辑对已有标签增加次要删除入口，仍走原删除确认。
- 缺库 Banner 在可用内容宽度至少 320dp 且字体缩放不超过 1.3 时将下载操作与说明横排；其他情况改为说明在上、下载操作在下。只呈现原下载动作，不自动开始下载。
- 字体缩放超过 1.3 时，底部导航继续显示目的地名称，标签最多换成两行，并增加导航栏最小高度；图标不再重复朗读标签。列表号码和时间允许自然增高换行。
- 记录卡片和详情身份区的处理结果直接按历史 `ResultType` 呈现。联网查询失败需明确标注 Fail Open/已放行并保留具体失败分类；社区快照和当前名单状态不能替代历史处理结果。
