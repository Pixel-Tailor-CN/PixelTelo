# 数据同步与通知策略

## 当前已实现的通知

### 离线库可用更新

- 自动检查默认关闭，启用后由 WorkManager 按用户设置的间隔执行，默认 24 小时。
- “自动下载数据库更新”默认关闭。关闭时，检测到新版本发送普通通知，点击打开应用，由用户确认下载；同一版本只提醒一次。开启后，周期检查发现新版本直接使用现有 WorkManager 任务下载并安装，允许移动网络，不再发送要求手动下载的提醒；入队失败时回退该提醒。手动检查仍需用户确认。
- Android 13+ 需要 `POST_NOTIFICATIONS`。未授权时不能开启自动检查，不影响手动下载与来电识别。

### 通话结束后的质量反馈

- 开关默认开启。符合官方反馈资格的放行记录可登记待提醒项；`CallStateReceiver` 收到 `IDLE` 后展示质量反馈通知。
- 通知提供准确／不准确操作；提交失败保持可重试，终态写回记录。权限缺失时静默跳过，不影响来电响应。
- 自建结果不能提交官方质量反馈，社区上报也不会由通知自动发起。

## 当前下载体验

用户手动确认或通过开关授权的自动下载由同一普通 WorkManager 唯一任务执行，页面从持久任务读取等待、进度、成功或失败状态。页面退出不取消下载，重新进入可继续观察。关闭自动下载只阻止尚未开始的自动任务，不取消已开始的下载。

**当前不发送下载进度或下载完成通知**，也没有实现 Android 16+ Live Update 或前台下载服务。不能把普通更新提醒、应用内进度与这些未实现能力混为一谈。同步验证与安装边界见[同步策略](../architecture/sync-strategy.md)。

## 尚未实施的展示方案

Live Update、前台进度通知及完成后版本／大小通知仅是后续可能的体验方向，需要独立明确需求、权限与系统 API 方案后才能实施；不属于当前交付或本次修复。
