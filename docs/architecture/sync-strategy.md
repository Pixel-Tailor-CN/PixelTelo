# 数据同步策略

## 初始化与完整性状态

离线 `MastDatabase` 安装时为空，运行时记录保存在独立的 `AppDatabase`。`SyncRepository` 在 IO 作用域异步读取离线库，不在构造函数中阻塞主线程。

仓库独立发布版本与 `isDatabaseReady`：只有可读取的正确 schema、非空版本和大于零的号码行数才视为就绪。主页消费就绪状态，缺库、损坏或“有版本但号码表为空”均提示用户下载初始化；不能只依据版本号隐藏提示。

## 持久下载与自动下载授权

1. 页面通过官方 `SyncApi` 检查版本，展示服务端的更新信息。
2. 手动检查由用户确认后入队；周期检查仅在“自动检查更新”和“自动下载数据库更新”都开启时自动入队。`OfflineDatabaseDownloadScheduler` 将地址、校验值、大小、版本、可用的预期行数及自动来源标记写入唯一的普通 `OneTimeWorkRequest`。
3. 任务使用 `KEEP` 合并重复请求；任何可用网络（包括移动网络）满足约束后由 `OfflineDatabaseDownloadWorker` 执行。自动下载开始前重新核对两个开关和本地版本，开关已关闭或该版本已完整安装时跳过，不展示虚假的“更新成功”。已开始的下载不因开关关闭而中断。
4. 页面观察唯一任务的 `WorkInfo`，区分等待网络/系统调度、下载百分比、校验、安装和终态。进度面板可收起，离开页面不会取消任务；点击离线数据库行可重新查看进行中的任务，重启应用后也可恢复观察。
5. 当前实现使用完整文件下载，不承诺断点续传。任务在进程恢复后可重新执行；失败不立即循环重试。用户可手动重新确认下载，或在自动下载仍开启时等待后续周期检查再次发现更新。

普通 WorkManager 下载不新增前台服务或运行时权限。下载进度显示在应用内，当前不发送下载进度或完成通知；通知现状见[通知规范](../ui/notifications.md)。

## 验证、连接与原子替换

- `SyncRepository` 独占缓存的 Room 连接，查询方通过 `lookupSpamNumber()` 读取结果，不取得或关闭数据库实例。
- 查询、状态检查、关闭和替换共用连接锁；下载本身不持有查询锁。更新与删除另用命令锁串行，避免迟到下载在删除后重新安装。
- 下载通过独立 OkHttp Call 执行；取消会关闭请求。响应与流使用可靠的关闭路径，日志仅保留错误分类，不打印可能包含签名参数的地址或响应。
- ZIP 必须符合服务端声明的字节数和 SHA-256；压缩文件上限为 512 MiB，解压数据库上限为 2 GiB。归档只接受根目录下唯一的 `mast_*.db` 候选，不按外部路径任意解压。
- 候选置于数据库目录，先使用正式 Room schema 校验，再检查版本、非空号码数据、服务端提供的预期行数及 SQLite `quick_check`。
- 候选验证失败不修改旧库。进入连接锁后关闭旧连接并完成旧 WAL/journal 处理，再通过同一文件系统的 `Os.rename` 原子替换；不预先删除旧主文件，也不以覆盖复制作为替换回退。
- 正式离线库的常规 Room 打开和旧日志探测均禁止损坏回调隐式删库。旧损坏库不能完成 checkpoint 时，先将主文件及日志整组保存在同目录恢复区，再安装已验证候选；失败或启动时按文件布局恢复，旧主文件最后恢复，避免新旧日志混用。
- 替换成功后才发布新版本和就绪状态。失败或取消清理候选与下载临时文件，保留原库；页面不得把读取或删除失败展示成成功。
- 删除号码库前先关闭自动下载，再取消唯一下载任务，由仓库等待更新命令结束并关闭连接、删除文件，防止排队任务或后续周期检查重新安装已删除的库。

## 周期检查与通知

“自动检查更新”默认关闭，开启后使用唯一 `PeriodicWorkRequest` 按小时级间隔调用 `/api/v1/sync/check`，默认 24 小时。开启或修改间隔后从当前时间计算首次执行时间。

“自动下载数据库更新”独立保存且默认关闭，位于自动检查设置下方；未开启自动检查时不可操作且不生效。关闭自动检查时保留自动下载偏好，重新开启后恢复生效。开启自动下载不立即检查或重置检查时间，仍沿用已有周期。

自动下载关闭时，自动检查对同一新版本提醒一次，由用户确认下载。开启时，新版本直接入队，不再发送要求手动下载的提醒；入队失败回退更新提醒，下载失败保留旧库。手动检查始终保留更新详情与确认流程。Android 13+ 未授予通知权限时仍不能开启自动检查，不影响手动下载与来电识别。

## 运行时数据的手动备份恢复

- 系统文件选择返回后，在 IO 调度器中打开、读取或写入文件；文件不可用、权限失效及空流都进入统一失败提示，可靠关闭流。
- 解析、导出和恢复期间禁止重复提交，并显示处理状态。恢复前预览并由用户选择数据范围。
- 所选来电记录、黑白名单及本地标签共享 `AppDatabase.withTransaction`，任一写入失败回滚本次恢复。本地标签保持原有校验、去重和跳过非法条目的统计语义；未选择的数据不读写。

## 官方同步与实时查询隔离

官方离线同步始终使用固定 Base URL、系统信任 TLS 和专用 `officialSync` Client；自建 URL、Token、SPKI Pin、Instance ID 和 source 配置不进入同步链路。

切换、阻止或查询失败的自建 Backend 不会停止官方离线更新。自建 Token 由 Keystore 保护并排除备份，不写入离线库或同步任务。

实时查询使用开始时取得的不可变 Backend Snapshot，网络超时为 1–10 秒、默认 5 秒并夹紧旧配置。自建失败全部 Fail Open，不自动回退官方实时查询。系统筛查另有独立响应预算，本地查询另有 3 秒硬上限，详见[原生集成](native-integration.md)。
