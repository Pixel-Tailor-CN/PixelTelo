# 数据同步策略

## 初始状态

* **空启动**: 应用程序安装时，本地 **Room** 数据库默认为**空**，以保持 APK 体积最小化（"极致轻量"）。

## 初始化工作流 ("空数据检测")

1. **App 启动**:
    * 主页面 (`HomeViewModel`) 检查数据库中的记录数。
2. **检测**:
    * **条件**: 如果 `count == 0`。
    * **UI 响应**: 显示醒目的“需要设置”或“下载数据”卡片。
3. **用户操作**:
    * 用户点击“下载”。
4. **下载与处理**:
    * **机制**: 使用 `WorkManager` 或前台 Service (Foreground Service)（不在主线程执行）。
    * **网络**: **Retrofit** 下载压缩的数据库/数据文件。
    * **存储**: 下载并校验数据库文件后替换本地 `mast.db`。
    * **完成**: 通知主页面刷新 UI（状态变更为“已填充”）。

## 云端更新

* **更新方式**: 当前客户端支持版本检查及完整数据库文件下载/替换；增量更新能力取决于后端协议。
* **自动检查**: 设置页提供“自动检查更新”开关，默认关闭。开启后使用 `WorkManager` 注册唯一
  `PeriodicWorkRequest`，按用户配置的小时级间隔检查 `/api/v1/sync/check`。
* **首次检查时间**: 用户开启自动检查或修改间隔后，从当前时间开始计算首次检查时间，默认 24 小时后执行。
* **提醒边界**: 自动检查只对比版本并在发现新版本时发送通知，不自动下载或替换 `mast.db`。下载仍需用户进入应用确认。
* **去重策略**: 同一个数据库版本只发送一次更新提醒，避免用户未更新时被周期性重复打扰。

## 官方离线同步的固定边界

* 官方离线同步始终使用固定 Base URL、系统信任 TLS 和专用 `officialSync` Client，仅创建 `SyncApi`。
* 自建配置只影响实时号码查询，不能修改离线数据库检查、下载地址、证书策略或 `MastDatabase` 路径。
* 切换到自建 Backend、运行期阻止自建 Backend 或自建查询失败，都不会停止官方离线更新；反过来，
  离线同步也不会读取自建 URL、Token、SPKI Pin、Instance ID 或 source 配置。
* 自建 Token 仅保存在 Keystore 保护且明确排除备份的独立凭据文件中，不进入离线数据库、同步请求、
  App 导出备份或设备迁移。

## 实时查询边界

* 实时网络查询超时由用户配置，允许范围为 1 至 10 秒，默认 5 秒；Repository 对旧配置再次夹紧。
* 一次实时查询使用开始时取得的不可变 Backend Snapshot 和对应 source 配置。Backend 切换不会改变
  已开始请求的目标。
* 自建查询的网络、鉴权、TLS、Pin、版本或身份失败全部 Fail Open，且不得自动回退或再次访问官方实时
  查询；需要持续阻止的安全错误由首页 WarningCard 提醒用户重新验证。

## 线程处理

* 所有数据库写入必须在 `Dispatchers.IO` 上执行。
* 来电查询 (`CallScreeningService`) 应该使用 `RunBlocking`（需谨慎）或具有严格超时的专用 Main-Safe
  异步操作，如果未使用专用查找结构，最好使用优化的非阻塞 IO。
