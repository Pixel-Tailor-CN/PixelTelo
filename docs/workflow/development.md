# 开发与技能维护工作流

按任务需要使用本文；项目约束与验证命令统一维护在 [AGENTS.md](../../AGENTS.md)。

## 从目标推进到完成

1. 确定预期结果，检查工作区已有改动，定位受影响的入口与调用链。按主题读取文档，不预读全仓库。
2. 常规修复直接实施；跨模块、迁移或有关键取舍时，用简短计划列出范围、依赖与验收方式。仅需跨会话跟踪时保存到 `docs/plans/`，不预先展开整份实现代码。
3. 完成已授权工作。只有无法从现状推断且会改变结果的问题才阻塞相关步骤；用户补充要求时沿用已完成工作并调整剩余步骤。
4. 按根规则的验证表检查并修复本次引入的问题。无新证据时不重复同一构建，也不机械执行全套设备检查。
5. 审查最终差异，更新被改动行为对应的文档，交付结果、验证证据和具体限制。环境阻塞与代码失败分开报告。

## 独立工作与审查

相互独立的搜索和读取可以批量并行；修改同一文件、共享 Gradle 构建目录或有先后依赖的操作按序执行。
当前会话允许委派且存在能独立完成的子任务时，按收益选择子代理，例如独立审查或不同模块调查。
交代目标、文件边界、必要背景与验收条件；主代理继续其他工作，合并结果时核对证据。
不为凑流程固定代理数量、模型档位或多轮审查，也不让多个代理重复构建同一工作区。

审查关注会改变正确性、隐私、来电响应或用户体验的问题。尤其检查本地与网络超时的区别、
通讯录放行、Backend 隔离、Room 迁移和取消路径。风格偏好不应扩大修复范围。
仅文档变更检查链接、事实来源、指令冲突与是否误写成已实现行为。

## 场景验证

仅选择本次改动影响的场景，具体操作沿用对应功能文档：

- 离线数据：空库提示、下载校验、替换失败、完成后 UI 刷新。
- 来电查询：通讯录与名单优先级、国际号码门禁、本地命中、联网成功/超时/失败放行；使用受控设备或模拟入口，不拨打真实业务号码制造测试来电。
- 原生集成：Pixel 拨号器标签、Provider 缓存刷新、Blocked Calls；模拟器结果不能代替 Pixel 真机结果。
- Backend 与凭据：切换中的请求归属、失败不回退官方、反馈隔离、日志与备份不包含敏感信息。
- UI：仅检查受影响的状态、权限拒绝和返回路径；新建安装或清空数据需使用可丢弃环境或已有授权。

构建、Lint 和设备命令及单元测试例外见根规则。依赖未变时不开展全量版本审计；依赖变更时验证兼容性，
说明采用预发布版的实际原因。Gradle 的 `clean` 只用于有证据的缓存问题，不作为每次构建前置步骤。

## Skills 的适用范围

仓库当前没有自定义 `SKILL.md`，普通开发使用根规则即可。不要为了包装已有规则新增“所有任务必用”技能。
有可复用的特定操作时，再创建 `.agents/skills/<名称>/SKILL.md`：

- YAML frontmatter 包含 `name` 与简短 `description`，写清操作和触发边界；不要用“只要涉及代码/数据库就使用”等宽泛描述。
- 正文说明必要输入、关键步骤、结果与停止条件；复杂资料移入 `references/` 并按需读取，脚本只承担需要确定性执行的操作。
- 不重复项目架构、通用能力或全量检查表，不强制串联其他技能，不引入逐步确认、固定 TDD 或自动提交。
- 用应触发、不应触发、缺少输入三类任务检查描述及执行行为。记录实际验证结果，静态检查不能宣称模型性能提升。

共享技能与插件缓存位于仓库外；本仓库的优化不修改这些文件，也不通过同名技能冒充覆盖。
若共享技能与项目约束冲突，按当前用户要求和项目适配处理；需要停顿时指出具体条款。
只为项目内可复现的问题新增规则，模型升级后重新审查，不累积历史补丁式指令。

## 历史计划与发布流程

`docs/plans/` 保存设计依据和实施记录。重新执行前确认哪些工作仍未完成，旧的技能指令、提交示例、
设备标识和绝对路径不作为本次执行依据；不要重演已完成步骤或将历史验证结果当作当前结果。

`.github/workflows/release.yml` 在推送 `v*` tag 后构建并发布 AAB/APK；
`auto-assign-issue.yml` 在 issue 创建时分配负责人。它们属于 CI，不是模型开发流程。
仅修改协作规则时不触发这些远程操作；修改 CI 时单独核对触发条件、权限、签名环境和产物。
