# 实时查询服务器配置与扫码交互设计

状态：2026-10-18 已实施，独立代码审查通过，已完成模拟器可用场景回归；真实服务与真实二维码等验证边界见实施计划。沿用设置页风格，原范围不含大字体适配。

## 目标与范围

让用户清楚知道当前使用哪个服务，能顺畅完成配对、修改、验证及失败恢复。修复顶部返回与系统返回不一致、错误远离输入字段、验证时跳回入口等问题。

只调整 UI、资源、必要的导航与 ViewModel 展示状态。保持唯一自建配置、已有验证流程、超时、凭据存储和 Backend 切换规则。不增加清除配置、多服务器、相册导码、闪光灯、权限、依赖或网络取消能力；自建失败不自动回退官方。

## 一、统一管理入口

“在线查询 → 实时查询服务器”始终进入全屏“查询服务器管理”，替代当前按状态分别出现的配对入口和管理弹窗。

页面使用现有 `SettingsSection`、`SettingsGroup` 和带图标设置行。官方、自建各自展示状态，不用点击即切换的单选按钮。状态由实际 Backend 与保存配置共同决定，不根据上次按钮点击推断。

| 状态 | 内容 | 操作 |
| --- | --- | --- |
| 官方在用，自建未配置 | 官方“使用中”；自建“未配置” | 自建组内直接提供“扫描配对码”“粘贴配对配置”“手动填写配置” |
| 官方在用，自建已保存 | 官方“使用中”；自建“已保存 · 未启用”，显示地址、版本、上次验证时间 | “验证并启用”“修改配置” |
| 自建在用 | 自建“使用中”，显示摘要；官方“未启用” | 自建“重新验证”“修改配置”；官方“切换至官方服务” |
| 自建不可用 | 自建“不可用”及现有错误分类；官方是否在用按实际状态显示 | “重新验证”“修改配置”，未使用官方时提供“切换至官方服务” |

已保存凭据的重验证沿用专用接口，不回填明文。切回官方保留自建配置；成功之后才更新使用状态。重验证发现安全不兼容时可能变为不可用，必须如实呈现，不能承诺仍使用旧服务。

不再单独设置“选择添加方式”页面。已有配置点“修改配置”直接进入预填地址和安全设置的表单，令牌为空；表单保留“扫描配对码”“粘贴配对配置”替换入口。已有实际修改时切换输入方式须确认丢弃本次编辑，已有保存配置保持不变。

## 二、手动填写与粘贴

手动页标题“手动配置”，分为“连接信息”“证书验证”两组：

- 基础字段为“服务器地址”“访问令牌”，令牌按现有规则遮蔽；地址示例 `https://mast.example.com/`。
- 默认“系统信任”，另一项“指定证书指纹（SPKI Pin）”；选择后才显示指纹输入。保留现有证书验证边界，用一句说明加按需帮助代替长段正文。
- 地址、令牌、指纹错误分别紧邻对应字段，定位首个错误；编辑字段后清理过期提示。不能仅在按钮之后显示笼统失败信息。
- 底部主按钮“下一步”，只进行本地校验，不发起网络验证。正文可滚动，底部操作避让键盘和手势区，不叠加重复 inset。

粘贴页统一为独立页面“粘贴配对配置”：遮蔽输入区、“从剪贴板粘贴”、就地错误及底部“下一步”。进入页面不读取剪贴板；只有明确点击或用户主动粘贴才导入。成功解析仅进入确认页，不访问服务器。

## 三、扫码页

独立标题“扫描配对码”，保留标准返回栏，其余空间由预览、短说明和底部操作区分配。取消固定 300dp 高预览、默认红线及多余大片空白；取景框受可用宽高约束，预览保持比例，不增加磨砂特效或新依赖。

底部常驻“粘贴配置”“手动填写”。离开扫码、切后台或进入确认后停止相机，重新进入才恢复。

| 状态 | 反馈与下一步 |
| --- | --- |
| 尚未授权／可以再次申请 | “扫码需要相机权限”，主按钮“允许使用相机”，保留替代入口 |
| 需前往系统设置授权 | 简短说明与“打开应用设置”，返回应用后重新检查权限 |
| 没有相机硬件 | “当前设备没有可用相机”，只提供粘贴和手动，不显示权限设置 |
| 相机启动失败 | 就地说明、可用时“重试”，保留替代入口 |
| 扫到非配对码／配置无效 | 暂停识别并就地显示原因，“重新扫描”才恢复，避免重复报错或退出流程 |
| 识别成功 | 停止预览，进入确认；不自动验证、不直接启用 |

权限状态需核对系统实际授权、可再次申请情况与申请历史；不能简单把“曾申请但未授权”全部当成永久拒绝。

## 四、确认、验证与重试

标题“确认服务配置”。紧凑摘要展示服务器地址、证书验证方式、必要的指纹信息及“访问令牌：已填写”；不显示令牌长度、片段或可复制明文。底部主按钮“验证并启用”，次操作“修改配置”。说明：“验证成功后启用此服务。”

- 验证中：保留摘要与当前页面；主按钮显示进度，禁止重复提交、修改与返回，不弹重复 Toast。使用既有超时，不硬编码或展示臆测时长。
- 新配置验证失败：停留确认页，按现有错误类别显示原因；地址与证书设置保留，令牌已消费清空。显示补填框、“重新验证并启用”和“修改配置”，不得返回初始入口。提示：“地址与证书设置已保留，请重新输入访问令牌。”
- 已保存配置重验证：在管理页原位置显示进度与结果，沿用保存凭据验证，不要求每次手输令牌；需要更换凭据时引导修改配置。
- 成功：回管理页，显示真实“使用中”状态和简短成功反馈。

不向普通界面新增 HTTP 代码或底层响应正文。草稿验证失败不提交新配置；当前服务是否可用仍以实际 Backend 状态为准。

## 五、返回与草稿契约

顶部返回与系统返回共用同一分发逻辑。键盘显示时，系统返回先遵循 IME 收起行为。

| 当前步骤 | 返回行为 |
| --- | --- |
| 管理页 | 返回在线查询 |
| 手动／粘贴输入页 | 无实际改动直接回管理；有修改或导入内容时确认放弃 |
| 扫码页 | 停止相机并回管理；尚未读取候选时无需放弃确认 |
| 确认页，来源为手动 | 回手动页，验证前保留本次临时输入 |
| 确认页，来源为粘贴 | 回粘贴页，验证前恢复可编辑内容；允许格式规范化，不要求还原空白排版 |
| 确认页，来源为扫码 | 清理候选，回扫码并重新取景 |
| 确认页点击“修改配置” | 进入预填手动页，之后确认页来源更新为手动，避免返回循环 |
| 验证中 | 保持页面，不退出、不新增取消网络行为 |
| 验证失败后返回输入 | 保留非敏感字段，不能恢复已消费的旧令牌；粘贴来源需重新粘贴，手动来源需补填令牌 |

放弃弹窗：“放弃本次配置？”；说明“未保存的内容将被清除。”；按钮“继续编辑”“放弃”。只看预填地址、没有修改，不算脏草稿。

草稿令牌只在当前配对界面的内存控件／候选中临时存在，不新增到 ViewModel、SavedState、数据库或日志。页面间转交时清理重复原始材料；粘贴返回时可从尚未提交的候选恢复输入并移交所有权。验证移交时清理 UI 副本，网络层拥有的数组按既有生命周期清理，不能提前清空正在使用的数组。真正放弃、离开流程或页面重建时清理临时凭据。不能声称所有 String 或 GC 内存均可可靠擦除。

## 六、视觉、实施边界与验收

沿用设置页横向 16dp、分组间距 24dp、组标题间距 8dp、组内行间距 2dp，以及现有 Material 3 动态配色和图标体系。“使用中”使用主题强调色，不硬编码绿色。手动、粘贴、确认页采用统一正文与底部操作容器；扫码使用满足可读性的遮罩和独立底部操作区。

预计涉及 MainActivity、SettingsScreen、自建服务相关 UI、SettingViewModel 必要展示状态及中英文资源。优先复用现有 SettingsGroup；不动 Repository、Provider、凭据存储、网络请求、权限和依赖。

实施后检查：

1. 四类管理状态、官方与自建切换、成功和失败后的真实状态。
2. 每个步骤顶部返回／系统返回、已输入草稿、修改配置、键盘、重建和验证中返回。
3. 扫码权限首次／拒绝／设置返回、无相机、错误码内容、重复识别、前后台切换及扫码后停止相机。
4. 字段校验、粘贴解析错误、失败补填令牌、重新验证、成功回管理。
5. 浅色／深色、按钮可点击范围、字段与错误的读屏语义；保留遮蔽同时验证编辑与粘贴动作。不做大字体验收。
6. 不新增、不运行单元测试，不跑 test/check；代码实施后运行 assembleDebug、lint、git diff --check，再做模拟器验收。真实服务验证与扫码识别需获准的测试配置，不以模拟器相机预览代替端到端结果。

## 讨论裁决

最终采用统一管理、独立扫码、就地校验与失败恢复，排除清除配置、单选切换、固定取景框尺寸、确认页直接退出、HTTP 码与固定验证时长等建议。最终文档不采纳“绝对防嗅探”“凭据完全不可残留”等无法保证的表述，也不将设计审查当作运行验证。

实施后根据实机审查收敛：手动和粘贴页固定底栏只保留“下一步”，替代入口放入滚动正文；剪贴板操作紧随输入框；确认摘要使用主题圆角卡片；相机不可用状态在预览区域集中呈现。网络、存储与权限边界不变。
