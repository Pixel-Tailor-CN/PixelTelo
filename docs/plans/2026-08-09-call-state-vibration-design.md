# 通话状态震动设计

## 背景

用户希望在通话接通和挂断时获得一次简短震动反馈。Android 面向普通第三方应用公开的
`PHONE_STATE` 只能稳定提供 `RINGING`、`OFFHOOK` 和 `IDLE`，去电进入 `OFFHOOK` 不代表
对方已经接通，因此不能把它作为去电接通事件使用。

本功能坚持隐私优先和最小权限原则，不申请特权电话权限，不使用 Accessibility，也不要求
Pixel Telo 成为默认电话应用。无法可靠识别的去电状态不产生震动，避免误导用户。

## 功能范围

- 在设置页“应用功能”分类新增“通话状态震动”开关，默认关闭。
- 开关说明始终明确展示：仅支持可靠识别的来电接通与挂断；受 Android 系统限制，去电不会震动。
- 开启后，来电从 `RINGING` 进入 `OFFHOOK` 时短震一次，表示用户已经接听。
- 已确认接听的来电从 `OFFHOOK` 进入 `IDLE` 时短震一次，表示通话已经结束。
- 未接来电、拒接来电、被拦截来电和去电均不震动。
- 功能关闭时不维护额外通话状态，也不触发震动。

## 状态模型

使用 `SharedPreferences` 保存一个最小状态，避免 `BroadcastReceiver` 实例重建以及系统重复发送
广播造成错误或重复震动：

1. 收到 `RINGING`：记录当前存在待接来电。
2. 已记录 `RINGING` 后收到 `OFFHOOK`：将状态更新为已接听，并触发一次接通震动。
3. 已接听状态收到 `IDLE`：清除状态，并触发一次挂断震动。
4. 待接状态直接收到 `IDLE`：只清除状态，不震动。
5. 没有待接状态时收到 `OFFHOOK` 或 `IDLE`：按去电或无关重复广播处理，不震动。
6. 开关被关闭时立即清除保存的通话状态，避免再次开启后消费旧状态。

双卡或系统重复广播可能为同一状态发送多次事件。状态转换只在首次进入目标状态时触发震动，
相同状态的重复广播不产生额外反馈。

## 震动实现

- 新增普通权限 `android.permission.VIBRATE`。该权限无需运行时申请，Android 震动 API 没有无需
  声明权限的等价替代方案。
- 通过 `VibratorManager`（Android 12 及以上）或兼容的 `Vibrator` 获取系统震动器。
- 使用短促、低打扰的单次震动效果；不启动 Service，不使用循环震动。
- 设备没有震动器、系统拒绝调用或发生运行时异常时，仅记录英文 warning 日志，不影响电话状态
  广播中的悬浮窗移除和反馈通知逻辑。

## 设置与文案

设置项位于现有 `AppFeaturesPreferences`：

- 标题：`通话状态震动`
- 中文说明：`仅支持可靠识别的来电接通与挂断；受 Android 系统限制，去电不会震动。`
- 英文资源同步提供对应含义，避免非中文系统回退到缺失文案。
- 默认值为 `false`，升级安装不会自动开启。

`SettingViewModel` 负责读取和更新配置。Receiver 直接读取同一份 `SharedPreferences`，避免把
电话状态处理依赖于设置页面或 ViewModel 生命周期。

## 现有流程集成

扩展现有 `CallStateReceiver`，但保持各项行为互不阻断：

- 每次 `PHONE_STATE` 广播先按开关处理通话震动状态。
- `IDLE` 到达时仍按现有逻辑移除来电归属地悬浮窗。
- 查询反馈提醒仍只消费现有待反馈标记。
- 震动失败不得提前结束 Receiver 或阻止现有逻辑执行。

不新增常驻组件、前台 Service、数据库字段或网络请求。
