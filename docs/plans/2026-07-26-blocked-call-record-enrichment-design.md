# 拦截记录信息增强设计

## 1. 背景

当前拦截记录只展示电话号码、拦截结果、标签和查询耗时。用户无法直接看到号码归属地；
联系人来电被拦截后，页面也不会显示联系人姓名。随着历史记录增加，当前一次性加载全部记录的方式
还会放大联系人查询和列表状态计算的性能开销。

本设计增强拦截记录的信息密度，同时保持来电拦截链路轻量：

1. 保存并展示查询结果中的省份和城市。
2. 动态解析联系人姓名，不把姓名快照写入数据库。
3. 使用 Paging 3 分页加载记录，只为已加载窗口解析联系人。
4. 在模拟器上验证大量记录下的滚动性能和显示效果。

## 2. 已确认的产品决策

| 决策项 | 结论 |
| --- | --- |
| 联系人姓名来源 | 展示时动态读取系统联系人 |
| 联系人姓名持久化 | 不持久化，不进入备份 |
| 归属地展示内容 | 只显示省份和城市 |
| 运营商信息 | 不存储、不展示 |
| 历史记录归属地 | 不回填，旧记录保持为空 |
| 手动联网重查 | 成功且返回归属地时更新当前记录 |
| 列表布局 | 姓名与号码同行，归属地独立成行 |
| 记录加载方式 | Paging 3 分页展示 |
| 最终设备验证 | 已启动的 Android 模拟器 |

## 3. 目标与非目标

### 3.1 目标

- 新产生的拦截记录能够保存查询结果中的省份和城市。
- 手动联网重查能够补充当前记录的省份和城市。
- 拦截记录能够识别普通号码、带 `+86` 的号码和带中国移动一卡多号前缀的联系人。
- 联系人改名、删除或新增后，页面能够在刷新联系人数据后反映最新结果。
- 记录数量较多时，不一次性从 Room 加载全部记录，也不扫描全部历史号码查询联系人。
- 联系人查询不进入 `CallScreeningService` 的实时来电响应链路。

### 3.2 非目标

- 不展示或持久化运营商、卡类型等信息。
- 不为历史记录批量联网补齐归属地。
- 不保存联系人姓名快照。
- 不新增联系人相关权限；继续使用现有 `READ_CONTACTS`。
- 不在本需求中重构与拦截记录无关的页面或数据层。

## 4. 整体架构

### 4.1 组件职责

- `SpamNumberRepository`：继续负责本地与云端号码查询，并在结果中携带
  `PhoneLocationInfo`。
- `TeloCallScreeningService`：只把已有查询结果传给 `BlockedCallRepository`，
  不访问联系人 Provider。
- `BlockedCallRepository`：持久化拦截记录的省份和城市，对外提供分页数据流。
- `ContactRepository`：封装 `ContactsContract.PhoneLookup` 查询、号码候选生成、
  去重调度、缓存与联系人变化监听。
- `HomeViewModel`：组合分页记录、黑白名单状态和联系人姓名映射，向 UI 暴露展示状态。
- `HomeScreen`：使用 Paging Compose 渲染列表，并把当前已加载号码集合通知
  `HomeViewModel`；不直接执行联系人查询。

### 4.2 数据流

```text
来电号码
  → SpamNumberRepository.checkSpam()
  → CheckResult.locationInfo
  → TeloCallScreeningService
  → BlockedCallRepository.insert()
  → Room 保存 province / city

Room PagingSource
  → Pager
  → HomeViewModel 合并黑白名单状态
  → PagingData<BlockedCallListItem>
  → HomeScreen
  → 当前已加载号码集合
  → ContactRepository 动态解析
  → 联系人姓名映射更新 UI
```

联系人数据流与来电识别数据流相互独立。联系人 Provider 变慢或不可用时，不得影响拦截决策。

## 5. 数据模型与迁移

### 5.1 `BlockedCall`

新增两个可空字段：

```kotlin
val province: String? = null
val city: String? = null
```

不新增 `operator`、`cardType` 或 `contactName` 字段。

### 5.2 Room 迁移

- `AppDatabase` 版本由 7 升级到 8。
- 新增 `MIGRATION_7_8`，分别为 `blocked_calls` 增加可空的 `province` 和 `city`
  文本列。
- 在 Koin 数据库构建配置中注册迁移。
- 升级时不更新旧行，旧记录的两个字段自然保持 `NULL`。

### 5.3 写入和更新规则

- 新拦截记录：查询结果包含非空归属地时写入省份和城市。
- 查询结果缺少其中一个字段时，只保存实际存在的字段。
- 手动联网重查成功后，`attachQueryResult()` 同步写回归属地。
- 重查响应没有归属地时，不清除记录中已经存在的省份或城市。
- 省份、城市中的空白字符串在写入前转换为 `null`。

### 5.4 备份兼容

- 备份格式版本由 3 升级到 4。
- `BlockedCallDto` 新增可空的 `province`、`city`。
- 导出新备份时保留归属地。
- 恢复 v1 至 v3 备份时，缺失字段按 `null` 处理。
- 联系人姓名不进入备份。

## 6. 分页设计

### 6.1 Paging 3 接入

新增 Paging 3 所需依赖，包括 Paging Runtime、Paging Compose 和 Room Paging。
`BlockedCallDao` 新增按 `blockTime DESC` 排序的 `PagingSource<Int, BlockedCall>` 查询；
现有快照查询继续供备份等一次性任务使用。

`BlockedCallRepository` 使用以下 `PagingConfig` 创建 `Pager`：

| 参数 | 值 |
| --- | --- |
| `pageSize` | 30 |
| `initialLoadSize` | 30 |
| `prefetchDistance` | 10 |
| `maxSize` | 90 |
| `enablePlaceholders` | `false` |

`HomeViewModel` 把分页流与黑名单、白名单 Flow 组合，在 `PagingData.map` 中生成
`BlockedCallListItem`，最后通过 `cachedIn(viewModelScope)` 缓存。

### 6.2 UI 加载行为

- `HomeScreen` 使用 `collectAsLazyPagingItems()`。
- 每条记录使用数据库 `id` 作为稳定 key。
- 首次加载为空时显示现有空状态。
- 追加加载时在列表底部显示轻量加载指示。
- 加载失败时保留已经显示的记录，并提供重试入口。
- Room 数据变化时由 PagingSource 自动失效并刷新。

### 6.3 联系人查询窗口

联系人查询范围以 `LazyPagingItems.itemSnapshotList.items` 中当前已加载的记录为准，
不会读取整张 `blocked_calls` 表。

UI 只上报已加载号码集合；`HomeViewModel` 对集合执行去重和防抖后调用
`ContactRepository`。Paging 最多保留约 90 条记录，因此单次联系人解析的输入规模有明确上限。

## 7. 联系人解析

### 7.1 匹配候选

每个记录号码按顺序生成去重候选：

1. 原始来电号码。
2. 去除国家码后的号码。
3. `PhoneNumberNormalizer.normalizeForLookup()` 得到的标准号码。

这使以下联系人存储形式能够互相匹配：

- `13812345678`
- `+8613812345678`
- 中国移动一卡多号前缀号码对应的真实号码

`ContactRepository` 以一批号码作为调度单位，在 IO 调度器中通过
`ContactsContract.PhoneLookup` 逐号码查询；每个号码命中首个有效姓名后停止尝试后续候选。
查询过程限制并发，避免短时间向联系人 Provider 发起大量请求。

### 7.2 缓存与刷新

- 使用有界 LRU 缓存保存号码到联系人姓名的结果。
- 未命中结果也短期缓存，避免滚动回同一页时重复查询。
- 通过 `ContentObserver` 监听联系人变化。
- 联系人变化后清空缓存，并只重新解析当前 Paging 已加载窗口中的号码。
- Repository 不记录联系人姓名日志。

### 7.3 权限与降级

- 有 `READ_CONTACTS` 权限时执行查询。
- 权限缺失、Provider 抛出异常、游标为空或姓名为空时返回未命中。
- 未命中时 UI 只显示号码，不显示错误占位。
- 联系人异常只影响姓名展示，不影响归属地、拦截记录和其他操作。

## 8. 页面展示

采用已确认的布局 C。

### 8.1 列表卡片

- 匹配联系人：首行显示“联系人姓名 + 号码”，右侧显示拦截时间。
- 未匹配联系人：首行只显示号码，不保留空姓名区域。
- 姓名过长时优先保证号码与时间可辨识，姓名使用省略号。
- 第二行显示归属地；省份和城市均为空时整行隐藏。
- 省份和城市相同时只显示一次，否则使用空格连接。
- 拦截结果、名单状态、骚扰标签、备注和查询耗时沿用现有信息层级。
- 不显示运营商。

### 8.2 详情 BottomSheet

- 匹配联系人时显示联系人姓名和完整号码。
- 显示格式化后的省份、城市。
- 归属地为空时不显示对应信息行。
- 拨号、复制、黑白名单、反馈和联网重查继续基于记录中的原始号码。
- 手动重查写回归属地后，当前详情和分页列表同步刷新。

## 9. 性能与隐私

- `CallScreeningService` 不查询联系人，保持原有实时响应性能。
- Room 只加载分页窗口，不为 UI 持有全部拦截记录。
- 联系人查询仅在 IO 调度器执行，不阻塞 Compose 主线程。
- 联系人输入先去重，查询结果使用有界缓存，Provider 请求限制并发。
- 不持久化联系人姓名，不把姓名写入备份或日志。
- 不申请新权限。

## 10. 异常处理

- Room 分页刷新失败：保留现有条目并显示重试入口。
- 联系人读取失败：记录英文警告日志并回退到号码，日志不得包含联系人姓名。
- 归属地为空：隐藏归属地，不显示“未知”等占位。
- 旧数据库升级：通过 v7 → v8 migration 保留所有旧记录。
- 旧备份恢复：省份、城市按空值处理。
- 手动重查未返回归属地：保留已有归属地。

## 11. 验证方案

项目约定默认不新增、不运行单元测试，本需求遵循该约束。

### 11.1 构建与静态检查

```bash
./gradlew :app:assembleDebug
./gradlew lint
```

### 11.2 模拟器验证

在用户已启动的模拟器上安装 Debug 包并验证：

1. 普通号码、带 `+86` 号码和带中国移动一卡多号前缀号码的联系人匹配。
2. 联系人新增、改名和删除后，当前已加载记录能够刷新。
3. 拒绝 `READ_CONTACTS` 后页面正常回退到号码。
4. 新拦截记录能够保存并显示省份、城市。
5. 手动联网重查能够补充归属地，空响应不会清除旧值。
6. v7 数据库升级到 v8 后旧记录和其他字段保持不变。
7. 新备份能够保存归属地，旧备份能够恢复。
8. 使用 Debug 测试数据构造大量拦截记录，检查首屏加载、连续滚动、追加加载、
   返回已浏览页面以及联系人刷新时的流畅度。
9. 检查列表卡片和详情 BottomSheet 是否符合布局 C，且没有运营商信息。

大量数据验证仅使用 Debug 包的数据目录；如需导入临时数据，验证完成后恢复或清理该测试数据。

## 12. 验收标准

- 新记录和成功重查记录能够持久化并展示省份、城市。
- 旧记录不自动回填归属地。
- 联系人姓名动态解析，联系人变化后不会永久显示旧姓名。
- 普通号码、`+86` 和一卡多号号码均能使用标准化候选匹配联系人。
- 列表以 30 条为一页加载，不再把全部记录读入 UI。
- 联系人解析范围不超过当前 Paging 已加载窗口，且缓存有明确上限。
- 联系人失败或权限缺失不影响拦截记录展示和操作。
- 列表与详情符合布局 C，不展示运营商。
- Debug 构建和 Lint 通过。
- 在已启动的模拟器上完成列表性能与显示效果检查。
