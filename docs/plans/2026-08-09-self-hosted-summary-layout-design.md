# 自建服务摘要布局设计

## 背景

在线查询设置页与自建服务管理对话框共用自建服务摘要组件。当前摘要把服务地址、版本和验证时间拼接在同一段文本中，窄屏下内容拥挤，自动换行也无法体现信息层级。

## 目标

- 设置页与管理对话框采用一致的摘要布局。
- 服务地址、服务版本、验证时间分别占一行，并保留适当的垂直间距。
- 显示完整的规范化服务地址，方便用户确认当前实例和排查配置问题。
- 不展示 Token、Authorization Header 或其他凭据。

## 展示内容

摘要按以下顺序展示：

```text
服务地址：https://example.com:8443
服务版本：0.1.3
验证时间：2026年8月9日 08:22
```

英文资源采用对应的 `Server address`、`Server version` 和 `Verified at` 标签。

服务地址使用已经通过配置校验并持久化的规范化 Base URL。配置校验继续拒绝 user info、query 和 fragment；摘要不会读取或拼接 Token。

## Compose 结构

保留 `SelfHostedBackendSummary` 作为两处界面的共享组件，将原有单个格式化字符串改为三个独立文本行。组件内部使用带小间距的 `Column`，每行由独立字符串资源生成，使系统字体放大和窄屏换行时仍保持清晰层级。

地址行允许自然换行，不使用省略号截断。版本与验证时间同样允许系统按可用宽度换行，避免横向溢出。

## 安全与隐私

服务地址是用户主动配置且需要核对的连接目标，不视为认证凭据，因此不再进行域名或 IP 打码。Token 仍只通过一次性 `CharArray` 传递和 Keystore 密文保存，不进入 UI 状态、字符串资源或日志。

## 验证

- 编译 Debug Kotlin。
- 构建 Debug APK。
- 运行 Android Lint。
- 在设置页和管理对话框检查三行布局、长地址换行以及中英文资源。
