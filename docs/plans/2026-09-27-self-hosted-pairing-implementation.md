# 自建服务配对体验实施计划

设计依据：[已确认设计](2026-09-27-self-hosted-pairing-design.md)。本次在当前会话内实施；验收后用户另行授权创建本地 Git 提交，不推送。

## 任务与接口

- [x] 统一输入解析：`SelfHostedPairingParser.kt` 输出规范化候选或稳定错误分类；成功对象持有可清零的 Token，扫码、粘贴和手动配置复用字段校验。
- [x] 独立配对页：`MainActivity` 管理页面显隐与返回设置；`SelfHostedPairingScreen` 渲染入口、编辑、确认及验证反馈；`SelfHostedQueryDialog` 仅保留管理；`SettingViewModel` 组织解析与既有验证调用，不保存明文 Token。
- [x] 输入组件：`SelfHostedPairingImport` 提供显式剪贴板读取与遮蔽输入；`SelfHostedQrScanner` 管理嵌入式 QR 扫描、权限拒绝、相机失败及生命周期。补齐中英文资源、可选相机声明和扫码依赖。
- [x] 文档与验证：更新需求和架构说明，执行 `:app:assembleDebug`、`lint`、`git diff --check`，在可用模拟器检查页面、无效输入、权限及导航；管理员完成设备复验，独立只读审查最终通过。

## 重点边界

- 无效输入、导入取消和验证失败不能替换已启用配置。
- 非字符串 Pin 不静默降级，非空 Pin 使用既有严格规范化。
- 明文输入不进入 SavedState、日志或 ViewModel 状态；一次性 Token 使用后清零。
- 扫码在暂停和离开界面时释放相机，不通过 Activity result 传递配对结果。
- 配对页隐藏主导航，失败可重新输入，成功回到设置；旋转后不得显示无凭据的可提交确认。

## 验证约束

不新增或运行单元测试，不使用真实网页凭据，不卸载应用、不清空数据、不触发发布。模拟器无法覆盖的真机扫码与有效服务联调须明确记录。
